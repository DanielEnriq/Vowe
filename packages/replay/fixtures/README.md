# Replay fixtures

Two fixtures, with deliberately different provenance. Which is which matters
when a test fails, so it is recorded here rather than inferred.

**No test reads `~/.claude`.** Everything the suite needs is in this directory.

---

## `vowe-session.sanitized.jsonl` — structurally real

A real Claude Code session, from Vowe's own first task, passed through
[`../src/sanitize.ts`](../src/sanitize.ts).

This exists because a hand-written transcript gets windowing subtly wrong. The
distribution of record types, the ratio of tool calls to messages, the size of
command output, the gaps between timestamps, the interleaving of results with
the calls that produced them — all of that shapes where window boundaries land,
and all of it is hard to invent convincingly. So the fixture that tests
windowing is a real trace with the private parts removed, not an imitation.

**Preserved**: record types and field structure, ordering, original timestamps,
tool-call/tool-result pairing, the overall size and rhythm of the session.
Windowing behaves on this fixture exactly as it behaves on a live one.

**Removed**:

| What | How |
|---|---|
| Credentials | Pattern match on the common key formats, replaced with `[REDACTED]` |
| Home directories | Any `/Users/<name>` or `/home/<name>` → `/Users/dev` |
| Usernames | Learned from paths and slugs in a first pass, then removed everywhere — including `ls -l` owner columns and Claude Code's own `-Users-<name>-projects-<x>` directory encoding, neither of which is a path |
| Machine-specific identifiers | Session and message UUIDs remapped to a stable synthetic series, consistently, so tool results still match their calls |
| Unrelated projects | Sibling project names, where they appear in a path |
| CLI bookkeeping | `attachment`, `cost-state`, `file-history-*`, `last-prompt`, `queue-operation` records dropped |

Regenerate with:

```bash
pnpm --filter @vowe/replay run sanitize \
  ~/.claude/projects/<project>/<session>.jsonl \
  packages/replay/fixtures/vowe-session.sanitized.jsonl \
  --max 200 --scrub summarizeflow --scrub civic-platform
```

The two `--scrub` names are the escape hatch, and are named here on purpose. The
general rules rewrite project names in path position; these two appeared outside
one — a working directory under a different tree, and a process title — and a
heuristic broad enough to catch them would have rewritten ordinary prose. Naming
them explicitly keeps the redaction readable instead of clever.

After regenerating, re-run the audit. It is the check that matters, because a
sanitizer that only mostly works is worse than none — it gets trusted:

```bash
F=packages/replay/fixtures/vowe-session.sanitized.jsonl
grep -c "$(whoami)" $F                                     # expect 0
grep -oE '/(Users|home)/[^"/ ]+' $F | sort -u              # expect only /Users/dev
grep -cE 'sk-ant-|sk-or-v1-|gh[pousr]_[A-Za-z0-9]{16}' $F  # expect 0
```

## `repeated-failures.synthetic.jsonl` — hand-authored

Generated by [`../src/make-synthetic.ts`](../src/make-synthetic.ts). Nothing in
it came from a real session.

A real transcript cannot be relied on to contain the behaviour the surfacing
path exists for, so that behaviour is constructed: a worker tries four
variations of the same deduplication fix across two files, and every run of
`test/reconnect.test.ts` fails on the same assertion with byte-identical output
(`expected 2 to be 1`).

Identical output each time is the point. What should be noticed is not that a
test failed — that is ordinary — but that the same test is failing the same way
after four different attempts, which is the difference between progress and a
loop. This is the fixture that exercises `surface_update` → `CommunicationPolicy`
→ an approved interruption.

Deterministic by construction: fixed start time, fixed increments, fixed ids. The
same file every time it is generated.

```bash
pnpm --filter @vowe/replay run make-synthetic \
  packages/replay/fixtures/repeated-failures.synthetic.jsonl
```
